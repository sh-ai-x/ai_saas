AI SaaS Real Integrations and Setup Guides

Status: Approved build extension for the existing local foundation.

Outcome

Connect server-side Google OAuth, one sandbox payment provider, and a real model provider while preserving the no-credential local demo and the modular-monolith ownership boundaries.

Implementation order

  1. Versioned API contracts and fail-closed configuration validators.
  2. Google authorization-code exchange and server-owned session.
  3. Toss or Lemon Squeezy sandbox checkout, confirmation, and webhook.
  4. OpenAI, Anthropic, and Gemini provider-neutral Agent adapters.
  5. Detailed web setup guides with a category sidebar.
  6. Contract, fixture, API, browser, and integration verification.

Trade-offs

The first deployment remains one process. Real providers are selected by environment and one payment provider is enabled at a time. This keeps the portfolio path almost free while making the external boundaries real and independently testable.

Safety gates

  • No secrets, access tokens, payment payloads, or model prompts in Git or logs.
  • Sandbox/test mode is mandatory outside explicitly approved production.
  • All effects use stable idempotency keys and server-side verification.
  • Provider failures are visible and bounded; no silent paid fallback.
